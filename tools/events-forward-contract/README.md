# Three-module Events forward-contract checks

This package adds executable compatibility checks for the exact accepted Forms, historical Events and manual Dream Team contracts. It installs fictional, empty databases only. It changes no application, permissions policy, migration, public build or hosted system.

Run `npm ci --ignore-scripts --prefix tools/backend-tests`, then `node tools/events-forward-contract/three-module.mjs` from the repository root. The source manifest verifies immutable Git objects; fetch full reviewed history, never replace missing objects with working-tree SQL. The pinned Forms fixture replays the accepted 27-migration current-schema baseline: 49 public tables, 76 application functions and 64 policies before these source-only additions.

The six install permutations add only the reviewed Forms three keys and Dream Team two keys to the existing registry. Existing table owners/ACL/RLS, policies and function definitions/owners/ACLs survive every intermediate stage. The exact registry key union, owner and ACL survive all orders. The Forms-last and Dream-last registry definitions retain different ordering of the same exact array entries; only that definition is normalized for the final catalog comparison. No other definition is normalized.

The tests call real SQL to prove module and organization denial, current Dream Team revocation, retained separate Forms/Events authority, rejected-write audit behavior and raw-table denial. An empty Dream Team domain stays empty: no applicant producer, Person inference, qualification or course certification is fabricated. PGlite results are not native concurrency or provider Auth evidence.

The dedicated workflow also runs each order in a separate PostgreSQL 17 service. Native mode requires `TEST_NATIVE_PG=1`, one valid `COMPOSITION_ORDER`, and an explicit `TEST_DATABASE_URL`. It reuses the hash-bound, previously reviewed adapter: only loopback, postgres owner, exact `forms_core_test` name and empty public schema are accepted. No hosted URL or local implicit fallback is permitted. Native matrix success is required before reporting native acceptance; this suite does not replace separate existing concurrency tests.

The Events SQL remains `tools/church-events/fixtures/20260928183137_events_calendar_v1.sql`, a historical installer used only as a fixture. It is not a reviewed forward migration or evidence of installation on any nominated target. In particular, historical `service_role` table privileges and the `private` schema usage/catalog execute exception require exact-target review, not automatic replay. `events_catalog` materializes occurrences and is unsuitable for a metadata-only preflight.

Remaining release gates: nominated target catalog and migration provenance; a separately guarded, reviewed Events forward package where required; explicit target/SQL approval; witnessed independent recovery; pinned protected preview and genuine Auth/permission/revocation acceptance; cleanup verification; separate website release approval. Supabase CLI remains the previously reviewed 2.81.3; this package does not upgrade to v3 or infer compatible behavior from version numbering.
