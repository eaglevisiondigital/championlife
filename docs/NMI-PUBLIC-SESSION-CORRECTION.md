# Existing NMI browser flow — source-only session correction

The exact historical public flow and client from `84b2d9ab398bb8046570019da26a5db67fe77467` are imported with original SHA-256 provenance in `tools/nmi/public-source-pin.json`. This is a narrow integration correction, not a replacement checkout. Neither file is in the public build manifest or mounted by public HTML. No configuration, gateway, migration, merchant routing or executor changed.

The original flow retained the donor's receipt after logout and a detached status handler could still issue requests. The corrected flow clears receipt, capability, payment token and controls on authentication changes, expiry and cached-page restoration. It aborts pending fetches and invalidates their generation; delayed create, token initialization, execution and status responses cannot restore the former session. Detached controls cannot submit. Auth errors and explicit 401/403 responses clear the page. SDK callbacks stay synchronous; no Auth await occurs within the callback.

The actual client requires literal `enabled:true`, checks its session/configuration again after asynchronous session lookup **before** submitting a request, and rejects responses after a changed session. Guest capability-based giving remains supported by the existing backend; this is not a new login requirement. Normal same-user initialization/token refresh remains usable. UNKNOWN execution still offers only status lookup, never an automatic replacement sale. Aborting a browser request does **not** prove a payment request already submitted to a provider was cancelled. Original backend authorization, durable idempotency and independently approved recovery remain authoritative.
