# Lessons 6–8 private workbook responses — uninstalled source

This extension adds private cloud save/load to the existing Lesson 6, 7 and 8 pages using the same `public.lesson_answers`, enrollment and private revision store already accepted for Lesson 5. It creates no parallel course, answer, identity or consent system. Original PDFs, videos, page design, device-note storage and navigation remain unchanged.

## Exact content boundaries

| Lesson | Response groups | Approved source structure |
| --- | ---: | --- |
| 6 — How to Obey God | 7 | Six numbered headings and the personal-application question |
| 7 — How to Experience God's Love and Forgiveness | 7 | Sections A–G |
| 8 — How to Be Filled With the Holy Spirit | 6 | Sections A–F |

The source catalogs in `tools/discipleship-progression/lesson-{6,7,8}-content.json` pin existing PDF SHA-256, exact heading/page and stable group IDs. Lettered uppercase headings are normalized to title case only. Each response group links to the complete original section, including its subquestions; one response box is not a claim that each subquestion is graded or answered. No invented twenty-question syllabus is imposed.

Lesson 7 section H explicitly asks the learner to write privately on paper and destroy that paper. It is intentionally **not collected as a retained cloud response**. Its group activity also remains in the PDF. Lesson 8 personal prayer and group exercises remain in the workbook; a saved response cannot assert that a spiritual experience or group activity occurred. Learners can leave groups blank. Existing private device notes remain separate and are never imported automatically.

Saving all response groups does not grant video-watch credit, advancement, completion or a certificate. The existing trusted-completion/profile boundaries remain lessons 1–4 with the existing 95% unique eligible watch requirement and durable answer contract. Extending that completion boundary requires separately reviewed exact lesson/media policy and trustworthy provider evidence. Videos 11–13 remain missing; Lesson 6's existing two video labels are not rewritten or interpreted as proof of a complete multipart set.

## Database and installation

New forward migration: `20261102200549_lessons_six_to_eight_owned_worksheets.sql`, generated by Supabase CLI 2.81.3 and **not installed on any hosted database**. Antecedent: accepted `20261102193245_lesson_five_owned_worksheet.sql` and its existing owned-worksheet/progression/completion dependencies.

The entire new migration must execute in one supported migration transaction. It acquires the existing worksheet writer mutex before checking the exact accepted private function hashes, version constraint and absence of unmapped lesson 6–8 answers. The same mutex already protects legacy answer/enrollment writes. A concurrent legacy write that commits first is observed and blocks installation; an installation that wins first seeds versions before subsequent writes invalidate them. Unknown existing answers must be preserved and independently reconciled, never deleted to force installation.

The migration widens only the existing version constraint/initialization and owned transaction's supported lessons/cardinality. No new tables, RLS, execution grants, public wrappers, Auth permissions, completion writes or historical migration rewrites are introduced. Initial and future enrollments receive private version rows 1–8. Existing lessons 1–5 retain their response contracts. A user/lesson-specific opaque UUID revision remains mandatory for each write, so same-user cross-lesson replay and cross-account replay reject. A failed write rolls back its answers and version together.

## Browser security

The existing shared runtime binds its fixed source contract to the page's configured lesson and exact answer IDs. It checks lesson, worksheet identifier, cardinality, revision and response content before rendering. Auth identity/token verification, synchronous callback cleanup, abort/generation invalidation, deadline clearing, denial/conflict handling, no local answer cache and no automatic UNKNOWN retry are preserved. Wrong-lesson responses cannot populate fields. Save buttons do not enroll or complete a learner.

## Evidence and release boundary

Targeted native PostgreSQL and PGlite fixtures test installation provenance/concurrency, owner and lesson isolation, stale/invalid versions, rollback, RLS, session retirement, future enrollment and no fabricated completion. Chromium/WebKit mobile/desktop tests exercise actual pinned SDK behavior with fictional intercepted Auth/RPC only, including account switching, delayed writes, stale handlers, denial, unknown outcomes, history, logout, expiry, wrong-lesson responses and double submissions. These are local checks, not genuine Supabase or playback-provider acceptance.

Release still requires independent review, target-schema/Auth permission compatibility, genuine authentication/private save-load acceptance, existing custody/recovery/cleanup gates and separate deployment/migration approval. Rollback preparation is disabling the new entry UI/writes while preserving all saved answers, revisions and evidence. Do not drop answers or restore an older function that misinterprets these records.
