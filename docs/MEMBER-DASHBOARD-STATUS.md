# Member dashboard activity status — source only

The existing My Discipleship dashboard called owner-writable `lesson_progress.status = completed` certified-looking “Complete” and counted it in “X of 13 complete.” The existing `getDashboard()` selects that compatibility projection, not the private trusted-completion audit. `20261102014452_prepare_trusted_lesson_completion.sql` explicitly distinguishes these sources. An isolated browser regression against the original page reproduces the misleading claim.

The corrected page labels valid `in_progress` and `completed` records as **Activity recorded**, and absent records as **No activity record**. Its existing bar and count measure unique numbered lessons with those records, bounded to 1–13. Invalid, duplicate, unknown-status and out-of-range records cannot inflate the count. This does not rewrite or discard any stored history. There is no new completion or enrollment inference.

The explanation makes the limits visible: activity does not prove watching or completion; Lessons 5–13 worksheet saves may not appear in this legacy summary; no activity record does not mean no study. All thirteen routes now describe their existing private cloud worksheets and correct save modes (automatic drafts for 1–4; explicit Load responses / Save responses for 5–13). Videos 11–13 remain coming soon. Device notes remain separate and do not sync. The reader link continues to let the existing private reader check eligibility; the dashboard does not claim a book was read or downloaded.

The existing shared Auth helper, user/course query predicates, account and generation checks, expiry and history invalidation remain unchanged. The dashboard renders no raw worksheet answers, notes or prayer fields. No backend query, SQL, SDK, permission, approved style/layout, artwork, route or private-reader control changed.
