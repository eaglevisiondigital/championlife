# Giving merchant routing

Funds, merchant destinations, gateways and MID routes are independent, reusable canonical entities. A destination names legal entity/deposit label, currency, gateway and processor route; it contains no secrets. Composite FKs require the destination, gateway and processor route to belong to the same organization and gateway. The initial two-level parent/child fund hierarchy and optional display groups are reporting structures, not merchant routing. Cycles, deeper nesting and stale revision changes are rejected; top-level funds may also receive gifts.

Deployment A: one Authorize.Net account/MID serves many funds; a multi-fund session can group compatible designations in one leg. Deployment B: one modeled NMI gateway has Main, Youth and Outreach MID routes; a 300/100/50 designation session creates three independent legs and one consolidated receipt for actual successful principal. Deployment C: multiple Authorize.Net/NMI accounts and separately scoped SowGo destinations coexist. Provider boarding must confirm actual account capabilities before activation. No native NMI split or cross-MID vault portability is assumed.

`giving_route` validates active funds, dates, destination and processor route. A session freezes destination/gateway/processor IDs and revisions, provider, environment, currency, MID/processor references, settlement label and fund revision. Lines freeze designation, tax eligibility, campaign/event and amount. Legs group by destination + gateway + processor route, never by fund hierarchy or checkout alone. Frozen route/principal triggers and append-only line history prevent an in-flight routing edit from moving settlement. Provider transaction identity is unique per gateway/MID route/reference and cannot be reassigned.

Champion Life and SowGo use separate organization-owned legal/merchant routes regardless of website origin. A user requires explicit permissions in each organization; a frontend brand parameter, shared account or outreach campaign is insufficient. Champion Life’s approved legal metadata can identify Living Faith Christian Center INC and Champion Life as the public-facing DBA without putting internal details in public pages. No real destination or grant is seeded by GIV-1.

Gateway metadata defaults disabled/unverified, can represent sandbox/live environments, and contains only nonsecret account labels/capabilities. Real secret bindings, tokenization and processor transports are a later gate. The processor-neutral model includes extension labels for Stripe Connect, PayPal, Square and external connectors without inventing implemented adapters.

Future form versions and text keywords resolve through this same route boundary. Keywords can override a destination only within the same organization; a keyword can choose the actual MID, not merely a report tag. Import mappings must explicitly review historical fund/merchant/donor identities.
