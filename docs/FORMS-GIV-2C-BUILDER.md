## Staff workflows

The accepted Staff Workspace gains a separate permission-filtered Forms group: Forms, Form Builder and Submissions. A page without a selected form starts at the form chooser. Forms list includes type, lifecycle, published version, update/publish times, canonical submission count, held payment configuration and organization. Create supports a blank form, synthetic Giving/Event demonstrations, organization selection and duplication. Duplicates start unpublished with separate identity/history. Publish, pause, resume and archive are distinct authorized actions.

Desktop has field library, canvas and selected settings. Tablet/390px use Fields/Canvas/Settings tabs. Pointer capture supports mouse/touch drag handles, library insertion and field moves across sections without depending on operating-system text/file drag. A bounded visual descriptor and canvas edge scrolling assist dragging; drop/cancel/revocation clears temporary drag state. Edit/Move Up/Move Down and Alt+Arrow keys provide a keyboard alternative. Tapping a library item switches mobile back to the canvas. Desktop/mobile modes share the same draft. Widths are full/half/third/two-thirds, sections carry 1/2/3-column layout and a future step key. Mobile stacks. Local undo/redo retains 50 changes. Autosave sends the expected revision, announces save state and retains local changes on conflict instead of overwriting. Publishing waits for a successful save and freezes the canonical version. Later editing creates a new draft.

## Field and condition contract

Library: Heading, Paragraph/Rich Text (safe plain/bold/italic/bullet formatting), Divider, Spacer, Name, Email, Phone, Address, Short/Long Text, Number, Currency, Date, Time, Dropdown, Multiple Choice, Checkbox, Checkbox Group, Radio Group, Yes/No, File, Signature, Hidden, Section, Fund, Gift Amount, Payment, Submit and explicit-purpose Consent. No executable HTML, arbitrary scripts or regex. Named safe patterns are alphanumeric/postal code. Options keep label/value/order/active/metadata; stable internal keys do not follow label edits. Duplicated fields/sections get new keys. Previously published fields cannot be deleted or rewritten.

Conditions use typed source/value, eight supported operators and show/hide/require/disable targets. A bounded acyclic graph includes section-to-child dependencies. Client and server derive effective state, including permanently server-owned hidden/read-only defaults. Unknown, hidden, disabled, malformed or missing required answers fail closed. Required/min/max/length/date/time/email/phone/choice/file validations are authoritative on the server. Availability uses explicit ISO instants or configured IANA timezone for local date/time; dates and final submission capacity are rechecked under the Forms lock.

Public renderer loads immutable published configuration and header snapshots. It provides label associations, grouped fieldsets, error focus, conditional controls and a safe success/reference state. Both approved logos are reused; Powered By Kingdom Propel permanently links to `https://kingdompropel.com` with `noopener noreferrer`. Stable direct URL is `/forms/<organization UUID>/<slug>` on the shared host; `form.html?organization=...&slug=...` is equivalent. Organization domains can later resolve tenant separately. Embed foundation remains same-origin under existing SAMEORIGIN headers; cross-origin resizing/messaging and allowlists require their own validated gate.

## Payment and canonical identity

Active public funds are canonical references, with parent labels/order, allowed subset/default and optional multiple lines. Gift amounts are exact integer minor units and display with canonical currency scale. Forms payment configuration contains classification, fixed/custom/minimum, fund and field references, recurrence choices, anonymity, receipt/fee hooks and explicit destination override. Payment configuration authority is distinct from editing/publishing. No card, CVV, bank account or tokenization input exists. The UI says provider not configured.

A payment-enabled response creates one pending canonical Giving Session/legs/lines through GIV-1. Retry returns the same submission/reference and session; changed content under the same key fails. Non-donation lines are frozen tax-ineligible before insertion, never retroactively updated. No ledger outcome, payment completion or receipt is fabricated. Recurrence answers remain held preferences. After explicit reviewed Person/Household linkage, separately authorized Forms/finance staff can create an idempotent canonical pledge or held recurring draft. Public forms never silently create/merge People or grant portal/staff access. New-person creation remains the existing authorized People workflow. Event/campaign/household/minor/waiver fields are references and compatibility hooks, not a replacement for accepted guardian, attendee or check-in architecture.

## Files, submissions and analytics

The `platform-form-files` bucket is private. Published field policy restricts type, maximum size and private/public visibility. Service-only reservation binds tenant, form, version, request and field; a signed upload cannot overwrite. Submission verifies matching stored object metadata and consumes the reference. Staff download first rechecks current user permission and exact submission/file scope, then signs for 60 seconds. Explicit public-file authorization checks the current published instance and public field policy; private files never gain anonymous access. No bucket listing or raw private-table policy is added. Storage upload/download integration must still be verified against hosted acceptance; local fixtures do not claim real Storage delivery. Orphan reservations expire; operational object cleanup is a later owner-controlled retention gate.

Typed answer rows preserve field/version/key/label, submitted value and text/numeric/boolean/date/structured values. Signature/consent records retain signer, exact text/version, purpose, choice and server time. Immutable submission identity prevents changing history; reviewed linkage is separately audited. Submissions list/detail filter by date/status/version/payment/link and show references, answers, files, agreements and audit. CSV is version-aware, scope-guarded and neutralizes spreadsheet formulas. Metrics use actual counts/status/date trends and canonical ledger totals by currency; conversion rate is null without tracking. Finance reports remain separately permissioned. Form domain events are held, with no Communications queue/delivery or arbitrary outgoing webhook URL.

## Security and verification boundaries

Distinct capabilities: `forms.read/create/edit/publish/archive/submissions.read/submissions.export/payment.configure`. Current verified identity and active organization grants are checked per operation. Explicit expiring form/campaign grants are separate, confer no finance configuration, and support exact-form event scope. All new raw tables use RLS and deny application access. Private helpers are denied except the authenticated/service entry points. Narrow public configuration/file wrappers follow the accepted public-registration pattern with fixed search paths; they do not grant anonymous private-schema usage. Service-only submit/Storage gateways use exact origins/hostnames, Turnstile, body/time bounds, trusted ingress HMAC and separately committed per-form network quotas. These gateways/configuration are not deployed by this build. Forms-only public challenge configuration defaults to null in `assets/js/forms-config.js`; a separately authorized build may inject `FORMS_PUBLIC_SITE_KEY`. Test keys are allowed only in a verified isolated preview. This does not modify Auth/OTP configuration.

Tests cover full migration replay, canonical models, security/tenant/direct-ID/permission boundaries, conditional validation, immutable history, files, pledge/recurrence, UI/DOM and stale-response clearing. Six real PostgreSQL races require eight separate overlapping backends and a coordinator: same-draft publish, same-revision save, duplicate public submit, payment session retry, final capacity and same field-key creation. Browser build QA uses disconnected synthetic data, not hosted acceptance. Full standard and Christmas regressions preserve prior packages, Auth and GiveHub.
