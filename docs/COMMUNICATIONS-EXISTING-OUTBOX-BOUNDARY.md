# Existing Core G/H1 outbox review adapter

This source-only adapter reads the existing `communication_outbox`, `communication_attempts`, and `communication_callbacks` shapes. It creates no second outbox, sender, consent store, provider configuration, schema or retry worker. The existing `normalizeOutcome` and disconnected consent review are reused. Tests invoke the existing fictional `acceptanceSink` locally; no network or real messages occur.

`reviewExistingOutbox` derives actor/session from a trusted authentication port. It captures the requested message/organization/campaign and checks existing recipient/channel/purpose/idempotency/sender/profile identity against a separately verified provider receipt. Current scoped consent and suppression, including STOP, are rechecked inside the final serialized outbox read. HELP or START cannot manufacture purpose consent. Email consent does not establish SMS consent. Old callbacks dedupe by the existing `(organization_id,provider,event_id)` key and conflicting message/outcome replays deny.

Queued zero-attempt records can be ready for independent review only. An uncertain post-handoff request remains uncertain and cannot cause automatic resend. A known provider ID can be proposed for the existing callback review; an unknown provider ID requires separate authoritative manual reconciliation. The existing callback path cannot safely bind an unknown receipt automatically. No fabricated SQL action is proposed. Existing delivered/accepted states never become unsent. All outputs retain `canSend:false`, `canAutomaticallyRetry:false`, `canWrite:false` and `canChangeConsent:false`.

## Trusted binding still required

The server must authenticate the live session, authorize exact organization/campaign/recipient review, and project only permitted message/attempt/policy/callback metadata. `withCurrentOutbox` must reauthenticate and hold the compatible existing `private.comm_lock` boundary while reading current authority, consent, suppression and dispatch history, until the asynchronous callback completes. No actual database binding is shipped here. Current source records lack a general outbox revision column: the port's revision is a monotonic snapshot/version contract, not a claimed new schema field. Full captured snapshot equality also detects changes during provider lookup. A future implementation must prove version and serialization semantics rather than merely label a timestamp a revision.

`verifyReceipt` must authenticate the actual provider and independently correlate its envelope with saved dispatch metadata. No caller-provided `verified` flag is admissible. The adapter tests this interface with synthetic results only. Existing acceptance-sink callback HMAC is not real Resend/SMS signature verification. Provider timestamps, signature validation, key rotation, bounded lookup and provider-specific authoritative rejection require their own reviewed adapters.

No record body, address, private pastoral content, donor/minor details, credentials or raw provider errors are returned. Scope mismatch, account change, consent revocation, missing proof, duplicate callbacks, malformed receipts and cancellation fail closed. Production dispatch must retain original `authorize_dispatch`/external authorization and database checks; this review result is never a send token or a replacement for those checks.
