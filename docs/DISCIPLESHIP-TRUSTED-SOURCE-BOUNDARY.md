# Trusted progression-source composition (source only)

`reviewTrustedProgression` composes the reviewed unique-interval gate with server session authentication, learner-owned durable evidence, a playback verification interface, and a final serialized fresh-ledger check. Caller input selects course/lesson only; learner and session derive from the server authentication port. The immutable captured request, ledger identity, media/version/policy, provider observation, envelope digest and expiry must agree. Changed ledger or revoked session denies. Conflicting replay denies; exact duplicate intervals add no credit. Durable worksheet metadata is owner/lesson bound and raw answers are not returned.

## Unimplemented trusted bindings — release blockers

No actual video evidence provider has been selected or accepted. `verifyPlayback` must independently authenticate the provider and verify its source semantics under a reviewed policy. A valid signature over browser telemetry is **not** independent actual-watch evidence and must never be translated to `independent_provider_observation`. Digest checking binds the observed envelope bytes; it is not signature verification. Even provider playback observations cannot prove human attention or comprehension.

`authenticate` must validate a current provider session, not trust an old JWT alone. `loadLedger` must use owner-bound backend reads. `withCurrentLedger` must reauthenticate and hold compatible transaction/serialization protection against all session, enrollment, media, receipt and answer changes until its callback finishes. It must advance a durable monotonic revision for every such change. Local tests exercise these contracts with fictional ports; they do not implement or prove provider/database locks. Receipt ingestion must preserve source provenance, enforce provider receipt uniqueness and bind identity/media/policy before ledger insertion. No client-provided approval flags are admissible.

The return is review evidence only (`canCommit:false`), never a capability or progress write. A future authorized write must perform fresh authorization in its own serialized database transaction. Lessons 11–13 deny missing media; 5–13 cannot complete from local notes. Existing lesson routes, PR57, personal answers, notes, SDK, RLS and migrations remain unchanged. Provider evidence, learner session acceptance, durable database binding and controlled rollout each remain separate gates.
